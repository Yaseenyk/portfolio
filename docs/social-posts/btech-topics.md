Layer-wise project division fails in review panels.

A common B.Tech CSE team split looks clean on paper: one student does frontend, one does backend, one does database, one does documentation.

It becomes weak in review.

If the panel asks “Which module did you build end to end?”, three members may not be able to defend the working flow. If they ask “Where is your code change?”, the answer becomes vague.

A stronger split is vertical slice ownership.

For example:
Member 1 owns login, role check, and session handling.
Member 2 owns file upload, validation, and storage.
Member 3 owns dashboard charts and API queries.
Member 4 owns reports, export, and audit logs.

Each member touches UI, API, database, errors, and test cases for one real feature.

This also makes staged reviews cleaner. In each review, every member can show a working slice, explain the design, and answer viva questions from code.

## Instagram

Layer-wise work breaks during viva.

If one person owns frontend,
one owns backend,
one owns database,
only one person can explain each part.

Review panels usually ask:
“Which module did you build?”
“How does data move end to end?”
“What happens if login fails?”
“Show your contribution in code.”

For B.Tech CSE teams, a better split is vertical slice ownership.

Example:
Member 1: auth flow
Member 2: upload + validation
Member 3: dashboard
Member 4: reports

Each person touches UI, API, DB, and testing.
