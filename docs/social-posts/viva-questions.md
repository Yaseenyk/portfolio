Panels test whether you built the project.

A final year viva usually goes beyond the demo. The panel may ask what your project does, but the sharper questions are about your decisions.

Why this dataset? Why this model? Why this table structure? Where is authentication handled? What happens if the API fails? What will break if two users submit at the same time?

I wrote a free guide that groups viva questions into six categories. One category is the one many students skip: failure cases.

Prepare answers for what goes wrong. Server down. Wrong input. Empty dataset. Slow query. Missing internet. Invalid login.

If you do not know an answer, say that. Then reason out loud. A calm debugging path is better than a confident bluff.

## Instagram

Most viva panels test whether you built the project.
Not just what it does.

This free guide lists 6 viva question types:
- problem statement
- dataset / inputs
- architecture
- code choices
- testing
- failure cases

The last one matters.
Example: “What happens if the API fails?”

Do not bluff.
Say: “I do not know the exact cause yet, but I would check logs, inputs, and exception handling first.”
